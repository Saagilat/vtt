# server — игра и панель администратора

Один бинарь, два режима запуска (D22):

| Режим | Порт | Что делает | Судьба при падении |
|---|---|---|---|
| `vtt --mode=game` | 443 | кампании, столы, WebSocket, туман, фишки | падает только игра |
| `vtt --mode=admin` | 8443 | вход администратора, нагрузка, обновление, логи | падение игры не отбирает панель |

## Границы

- **Целевая машина: 1 ядро, 512 МБ, без видеокарты, Debian** (D18). Разметка карт в этот
  бюджет не входит: её считает машина мастера (D35). Если на сервере появится своя тяжёлая
  работа, она живёт отдельным процессом с ограничением (D14).
- **Разметку сервер не придумывает.** Он получает `annotation.json`, проверяет его по схеме
  из `../contract/` и хранит. Кто произвёл файл — разметчик на машине мастера, рука мастера
  или будущий чужой инструмент — сервер не знает и не должен знать (D11, D35). Отдельной
  «доверенной» ветки проверки для своего результата нет.
- **Решает сервер, а не клиент** (D06). Всё, что попадает в клиент или в браузер, доступно
  человеку, поэтому секреты (в том числе стены до открытия) не приходят ни в клиент,
  ни в браузер (D10).
- **Никаких чужих облаков** для картинок и звука (D17).

## Что здесь будет

Go-модуль, точка входа `cmd/vtt`. Первый шаг — не игра, а скелет с двумя режимами и
проверкой контракта: пока разметчика нет, серверу нечего проверять, но команда сборки
и тесты должны существовать с первого коммита.

Требования к поведению — [../docs/01-users-and-roles.md](../docs/01-users-and-roles.md)
и [../docs/06-admin-and-access.md](../docs/06-admin-and-access.md).
