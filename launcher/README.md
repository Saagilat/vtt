# launcher — установка и обновление клиента

Одна программа, которую человек запускает сам: она ставит клиент и его пакеты, приводит их
к нужной версии и только потом запускает клиент. Инсталлер — её первая роль; после установки
она остаётся рядом и работает лаунчером (D37, D39).

**Где живёт.** На машине каждого участника стола, рядом с клиентом, в одном каталоге установки.
Это единственная программа проекта, которая стоит у всех: клиент ставят все (D36), сервер —
один человек, разметчик — только мастер и только по желанию (D37).

## Границы

- **Не часть клиента.** Отдельная программа и отдельный проект (D39). Она работает, когда
  клиента ещё нет или он сломан, и переживает замену клиента — в этом весь смысл.
- **Ни одного адреса сервера** (LAU-01). Лаунчер не знает, к какому серверу подключится человек:
  адрес — настройка клиента. Вход лаунчера — манифест и файлы рядом ([MANIFEST.md](MANIFEST.md)).
  «Нужна версия не ниже X» — ответ сервера клиенту при входе, а не входные данные обновления.
- **Не решает, чего человеку не хватает.** Ставит то, что записано в манифесте: `client`
  обязательно, `voice` и `annotator` — только действием человека (D37). Молча доставляется
  только обязательное ([Q42](../docs/03-open-questions.md)).
- **Не сервер.** `vtt install`, `vtt update`, `vtt migrate` — подкоманды серверного бинаря
  ([SRV-08](../server/DECISIONS.md), [../server/ADMIN.md](../server/ADMIN.md), §8). Общее слово
  «обновление» не делает их одной программой: у сервера обновляются база и миграции, у клиента —
  файлы.
- **Секретов не хранит.** Ни ключей, ни паролей, ни адресов: только файлы поставки и их хеши.
  Нужна ли подпись сверх `sha256` — [LAU-Q3](QUESTIONS.md).

## Что внутри (план, кода пока нет)

| Часть | Задача |
|---|---|
| `manifest` | прочитать `latest.json`, проверить версию манифеста, собрать список файлов |
| `fetch` | скачать недостающее, сверить размер и `sha256`, докачать после обрыва |
| `store` | разложить по каталогу установки, держать рядом две версии, включать одну переключением |
| `launch` | запустить клиент, дождаться выхода, вернуть его код |
| `install` | поставить из файла: тот же манифест и те же файлы, только источник — каталог или архив |
| `report` | сказать словами, что стоит и чего не хватает (`--check`) |

Правило раскладки одно: старые файлы не перезаписываются на месте. Новая версия скачивается
рядом, проверяется и включается одним переключением; не получилось — остаётся прежняя. Иначе
обрыв на середине оставит человека без клиента вместо прошлой версии.

## Интерфейс (то, о чём договариваемся с клиентом)

```sh
vtt-launcher                            # доставить недостающее и запустить клиент
vtt-launcher --check                    # сказать версии и чего не хватает, ничего не менять
vtt-launcher --install <каталог|архив>  # поставить из файла, без сети
vtt-launcher --packages voice,annotator # доставить необязательные пакеты по просьбе человека
```

- лаунчер передаёт клиенту каталог установки, клиент отвечает на `--version`; больше между ними
  ничего нет — ни сокета, ни порта. Та же граница, что у разметчика
  ([../docs/07-projects.md](../docs/07-projects.md), §2), и по той же причине: это две программы,
  а не одна;
- сеть не нужна ни для `--check`, ни для `--install`: игровой вечер без интернета не должен
  зависеть от доступности чужого сайта (D37);
- вывод — человеческий текст на экран и в журнал рядом с установкой; код возврата: 0 — сделали,
  что просили, 1 — доставить не удалось (сети нет, хеш не сошёлся, нет места), 2 — доставили,
  но запустить не удалось.
