# Манифест поставки — формат `latest.json`

> **Зачем.** Лаунчер не знает, что лежит в релизе: он скачивает один маленький файл и по нему
> решает, чего не хватает на машине. Формат этого файла — такой же контракт, как `annotation.json`
> в [../contract/FORMAT.md](../contract/FORMAT.md), только между релизом и лаунчером.
>
> **Статус: решено, и формат читается кодом.** Исполняет его `launcher/internal/manifest`,
> и каждое правило из раздела «Правила» там — отдельная проверка с тестом. Формат защищён
> от «лишнего»: чего нет в таблице ниже, то не разберётся.

## Где лежит

Один файл `latest.json` в ассетах релиза, по одному адресу:

```
https://github.com/Saagilat/vtt/releases/latest/download/latest.json
```

Лаунчер делает один GET на старте. Нет сети, 404 или мусор вместо json — молча продолжаем с тем,
что установлено: игра не должна зависеть от доступности чужого сайта. Других запросов
к хостингу при запуске нет.

## Пример

```json
{
  "manifest": 1,
  "release": "1.4.0",
  "packages": [
    {
      "name": "client",
      "version": "1.4.0",
      "file": "vtt-client-1.4.0-win64.zip",
      "sha256": "9f2c4d0e…",
      "size": 41234123
    },
    {
      "name": "voice",
      "version": "0.3.1",
      "file": "vtt-voice-0.3.1-ru.zip",
      "sha256": "1b7a9c55…",
      "size": 81234567,
      "min_client": "1.4.0"
    },
    {
      "name": "annotator",
      "version": "0.2.0",
      "file": "vtt-annotator-0.2.0-win64.zip",
      "sha256": "c40d81f2…",
      "size": 21000000,
      "min_client": "1.4.0"
    }
  ]
}
```

## Поля

| Поле | Обязательно | Что значит |
|---|---|---|
| `manifest` | да | версия самого формата, сейчас `1`; незнакомая — обновление не применяем |
| `release` | да | версия релиза, к которой относится манифест; попадает в `--check` и в журнал |
| `packages` | да | список файлов; порядок не важен, повтор `name` — ошибка |
| `packages[].name` | да | `client`, `voice`, `annotator`; незнакомое имя — ошибка, а не «пропустим» |
| `packages[].version` | да | версия пакета; сравнивается с установленной |
| `packages[].file` | да | **имя файла в этом же релизе**, а не адрес: URL собирается от релиза |
| `packages[].sha256` | да | хеш архива, hex в нижнем регистре |
| `packages[].size` | да | размер в байтах: обрыв скачивания виден до распаковки |
| `packages[].min_client` | нет | минимальная версия клиента, с которой пакет работает |

`file` — имя, а не ссылка, намеренно: манифест не может увести лаунчер на чужой хостинг, даже
если его самого подменили. Байты качаются из того же релиза, откуда пришёл манифест. Подмена
самого манифеста при этом остаётся, поэтому доверие к релизу — доверие к аккаунту; подписи сверх
`sha256` в первой версии нет — [README.md](README.md).

## Правила

1. **`client` — ровно одна запись и всегда.** Без него поставка пустая: клиент и есть то, что
   человек запускает. `voice` и `annotator` — необязательные, их отсутствие не ошибка.
2. **Тишина — не согласие.** Незнакомое поле или имя пакета — ошибка разбора, а не «ну ладно»:
   так подмена не проходит молча. То же правило, что в
   [../contract/README.md](../contract/README.md), правило 4.
3. **Манифест меняется только с версией.** Новое поле — новый номер `manifest`; незнакомую
   версию лаунчер не применяет и продолжает работать с установленным.
4. **Пакеты одного релиза.** Клиент и пакеты берутся из одного `release`: смешивать версии
   из разных релизов нельзя, иначе «поставил голос — сломал клиент».
5. **Хеш — про порчу, а не про доверие.** `sha256` ловит битый файл и обрыв; подмену на стороне
   аккаунта GitHub он не ловит.
6. **Имена файлов — часть контракта.** `file` не сочиняется при сборке: список имён фиксирован
   в [../docs/how-it-works.md](../docs/how-it-works.md) («Поставка»), и сборка берёт их оттуда,
   а не наоборот. Релиз собирает CI из тега, а не рабочая машина.

## Установка из файла

Тот же манифест и те же файлы, только источник — каталог или архив, который человек принёс
на флешке: `vtt-launcher --install <каталог|архив>`. Отличие одно — нет сети, поэтому нет
и вопроса «а вдруг новее». Формат от источника не зависит: иначе появился бы второй формат,
который надо держать в согласии с первым.
