# annotation.preview.json — что нашлось, включая отрезанное

Рядом с `annotation.json` разметчик всегда пишет второй файл — `annotation.preview.json`. Это тот
же документ с теми же элементами плюс `confidence` у каждого. Он существует ради одного: мастер
должен видеть, что отрезал порог, а не гадать, чего не хватило.

Файл видят двое: разметчик, который его пишет, и клиент, который по нему рисует подсветку. Сервер
его не получает никогда — импорт несёт `annotation.json`, поэтому в контракте предварительного
файла нет ([../contract/FORMAT.md](../contract/FORMAT.md), §9).

## Из чего состоит

| Поле | Как | Зачем именно так |
|---|---|---|
| `format_version`, `image`, `grid` | один в один как в результате | подсветка рисуется поверх той же картинки, и сетка у двух файлов не может быть разной |
| `walls`, `doors`, `areas` | те же элементы и те же `id`, плюс `confidence` у каждого | по `id` клиент находит элемент результата: подсветка указывает на него, а не на «где-то рядом» |
| `confidence` | число `0 ≤ c ≤ 1` у каждого элемента | одно число, а не слово: полосы — оформление, и живут они в клиенте |

Элементов в предварительном файле не меньше, чем в результате, и все элементы результата есть в нём
с той же геометрией. Обратное неверно: найденное ниже порога остаётся только здесь.

## Инвариант

Три правила, и они проверяются кодом — `annotator/tests/check_preview.py` на примере
`annotator/examples/annotation.preview.json`.

1. Предварительный файл без `confidence` проходит контракт версии 1: та же схема, те же смысловые
   проверки, включая пределы. Лишних полей, кроме `confidence`, в нём нет.
2. Каждый элемент результата есть в предварительном файле с тем же `id`, той же геометрией и тем же
   `type`: подсветка на исчезнувший элемент хуже, чем её отсутствие.
3. `format_version`, `image` и `grid` у двух файлов совпадают — они сделаны одним прогоном по одной
   картинке.

Результатом прогона в проверке считается пример из контракта:
`contract/annotation.v1.example.json` — тот же документ, который читают оба валидатора. Пример
`annotator/examples/annotation.preview.json` — он же плюс три элемента ниже порога, и это
единственное их отличие.

## Чего в нём нет

- нет своего формата: новых видов элементов, полей и номеров версий в предварительном файле быть не
  может — он не версионируется и не переживёт расхождения с результатом;
- нет порога: файл не фильтруется, в нём лежит всё найденное;
- нет состояния: дверь открыта или закрыта — это сцена, а не разметка;
- нет пути на сервер: импорт берёт `annotation.json`, а файл рядом с ним никого не интересует.

## Как он меняется

Файл меняется свободно, пока разметчик и клиент договариваются между собой
([../contract/README.md](../contract/README.md)): в контракте его нет, версии у него нет. Граница —
инвариант выше: изменение, которое его ломает, это новая договорённость двух проектов, а не тихое
поле.

Где проходят границы полос уверенности — открытый вопрос
([../docs/open-questions.md](../docs/open-questions.md#формат-карты)): в файле только число,
а «высокая», «средняя» и «низкая» — константы клиента, и брать их пока не из чего.
