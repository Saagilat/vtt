# annotator — разметчик карт

Берёт картинку карты и выдаёт `annotation.json`: сетку, стены, двери и области
(вода, лава, тяжёлый рельеф). Что именно и в каких единицах — [../docs/05-map-annotation.md](../docs/05-map-annotation.md).

**Где живёт.** На машине мастера, рядом с клиентом. Ставится отдельным пакетом (D37) — его нет,
пока мастер не решит разметить карту. Запускает его клиент, дожидаясь как обычного процесса
(D35). На сервер разметчик не ставится и сервером не вызывается.

## Границы

- **Не служба.** Ни порта, ни демона, ни сети: вход — файл, выход — файл. Чужих сервисов
  тоже нет (D17). Единственный интерфейс — командная строка.
- **Только процессор.** Видеокарта не предполагается: классическое зрение (градиенты, линии,
  морфология) на CPU укладывается в бюджет эксперимента [04](../docs/04-experiment-map-layout.md).
  Эталонная машина — ноутбук мастера, 4 ядра, 8 ГБ ([04](../docs/04-experiment-map-layout.md), §6).
- **Отдельный процесс, а не библиотека.** Клиент запускает его и ждёт: поэтому граница —
  процесс, а не импорт, и поэтому же прогресс идёт в stderr, а результат в файл.
- **Про сервер не знает.** Разметчик не знает, куда уедет файл и что с ним сделают. Сервер
  получает готовый json и проверяет его сам (D11, D35) — в том числе когда файл нарисован
  рукой, а не этим инструментом.
- **Ничего не решает про видимость.** Туман, стены и секреты — работа сервера (D10). Разметчик
  только поставляет геометрию.

## Интерфейс (то, о чём договариваемся с клиентом)

```sh
vtt-annotate --image карта.jpg --out annotation.json      # разметить
vtt-annotate --image карта.jpg --out overlay.png --render # нарисовать, что нашлось
vtt-annotate --check annotation.json                      # проверить чужой результат
```

- результат — только файл; прогресс и предупреждения — в stderr, чтобы stdout оставался чистым;
- код возврата: 0 — разметка записана, 1 — вход не годится, 2 — внутренняя ошибка;
- частичный результат не записывается: либо файл целиком, либо ничего.

## Что внутри (план, кода пока нет)

| Часть | Задача |
|---|---|
| `grid` | проверка напечатанной сетки по профилю яркости; автоподбор — её частный случай (ANN-01) |
| `walls` | линии стен с уверенностью на всю стену (§6) |
| `doors` | проёмы в стенах, штрихи по краям (§7) |
| `areas` | вода, лава, тяжёлый рельеф (§8) |
| `render` | `overlay.png` поверх исходной карты — «похоже ли на правду» глазами |
| `validate` | проверка по схеме из `contract/`, с набором заведомо плохих случаев |
| `fixtures` | генератор синтетических карт с точным эталоном (ANN-02) |

## Состояние

Кода нет. Прототип (`tools/make_synthetic.py`, `tools/render_overlay.py`,
`tools/validate_annotation.py` и фикстуры `tests/`) снят с рабочего дерева (D34) и лежит
в истории репозитория — коммит `2c504fb`. Он писался под эксперимент, поэтому в проекте
пишется заново, а не переносится как есть.

Фикстуры вернутся сюда же, в `annotator/fixtures/`, но только синтетические: репозиторий
публичный (D38), а лицензии настоящих карт не проверены, поэтому в git они не попадают.
Настоящие карты остаются у мастера локально и поднимаются из коммита `2c504fb` — на них меряют
время, память и «похоже ли на правду».

На чём писать и как упаковать пакет — [ANN-Q5](QUESTIONS.md): Python удобнее для
эксперимента, Go легче по весу. Пакет собирается из этого проекта и лежит ассетом в релизе
(D38), поэтому его вес платит только тот, кто разметку ставит, а не все игроки за столом.
