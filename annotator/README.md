# annotator — разметчик карт

Берёт подготовленную картинку карты ([../prep/README.md](../prep/README.md)) и выдаёт
`annotation.json`: сетку, стены, двери и области (вода, лава, тяжёлый рельеф). Что именно
и в каких единицах — [../contract/FORMAT.md](../contract/FORMAT.md).

**Где живёт.** На машине мастера, рядом с клиентом. Ставится отдельным пакетом — его нет, пока
мастер не решит разметить карту. Запускает его клиент, дожидаясь как обычного процесса. На сервер
разметчик не ставится и сервером не вызывается.

## Границы

- **Не служба.** Ни порта, ни демона, ни сети: вход — файл, выход — файл. Чужих сервисов
  тоже нет. Единственный интерфейс — командная строка.
- **Видеокарта обязательна: 4 ГБ видеопамяти, марка любая.** Стены, двери и области ищет модель
  с открытыми весами, а её считают на карте; путь «на процессоре помедленнее» не обещаем — там
  та же работа идёт в разы дольше. Требования к машине целиком —
  [how-it-works.md](../docs/how-it-works.md), раздел «Машины»; сколько занимает прогон —
  [docs/experiment-map-layout.md](../docs/experiment-map-layout.md).
- **Отдельный процесс, а не библиотека.** Клиент запускает его и ждёт: поэтому граница — процесс,
  а не импорт, и поэтому же прогресс идёт в stderr, а результат в файл.
- **Про сервер не знает.** Разметчик не знает, куда уедет файл и что с ним сделают. Сервер
  получает готовый json и проверяет его сам — в том числе когда файл нарисован рукой, а не этим
  инструментом.
- **Ничего не решает про видимость.** Туман, стены и секреты — работа сервера. Разметчик только
  поставляет геометрию.

## Интерфейс (то, о чём договариваемся с клиентом)

```sh
vtt-annotate --image карта.jpg --out annotation.json      # разметить
vtt-annotate --image карта.jpg --out overlay.png --render # нарисовать, что нашлось
vtt-annotate --check annotation.json                      # проверить чужой результат
```

- результат — только файл; прогресс и предупреждения — в stderr, чтобы stdout оставался чистым;
- рядом с результатом всегда пишется `annotation.preview.json` — тот же формат плюс числа
  уверенности у каждого элемента. Это файл для глаз мастера: клиент рисует по нему подсветку,
  на сервер он не уезжает. Что в нём обязано совпадать с результатом — [PREVIEW.md](PREVIEW.md);
- `--min-confidence` задаёт порог: в `annotation.json` попадает только то, что не ниже него.
  Ползунок порога в клиенте не фильтрует готовый файл, а перезапускает разметчик с новым
  значением — так порог живёт в одном месте;
- код возврата: 0 — разметка записана, 1 — вход не годится, 2 — внутренняя ошибка;
- частичный результат не записывается: либо файл целиком, либо ничего.

## Что внутри (план, кода пока нет)

| Часть | Задача |
|---|---|
| `detect` | модель сегментации по подготовленной картинке: маска стен, дверей и областей. Веса — готовые или свои обученные, это открытый вопрос |
| `grid` | поля сетки по профилю яркости: дешёво, детерминированно, без модели; автоподбор — подсказка мастеру, а не решение за него |
| `vector` | маска → полилинии стен, двери с типом, прямоугольники областей. Сомнение «стена или тень?» — на всю стену, и только в предварительный файл |
| `render` | `overlay.png` поверх исходной карты — «похоже ли на правду» глазами |
| `validate` | проверка по схеме из `contract/`, с набором заведомо плохих случаев |
| `fixtures` | генератор синтетических карт с точным эталоном |

## Пиксели не трогает

Разметчик читает картинку и выдаёт геометрию — больше ничего. Напечатанную сетку к этому моменту
уже стёрла подготовка карты; повторять это здесь нечем: свободной кисти у разметчика нет,
картинки на выходе он не пишет.

Из этого следуют две вещи, ради которых этап и разделён. Первая: стирание не может уничтожить
стены и пол, потому что разметчик вообще не пишет пиксели. Вторая: «плохо разметилось» и «плохо
стёрлось» — две разные жалобы, и распутывать их не надо: у каждой свой этап, свой вход и свой
повторный прогон.

Сетку для автоподбора разметчик ищет сам, по профилю яркости, но найденное — подсказка: в файл
попадают поля, которые утвердил мастер, а не «предложенные»
([../contract/FORMAT.md](../contract/FORMAT.md), §5). Совпадение с тем, что нашла подготовка,
ничего не значит: у этих двух поисков разные задачи и общего кода между ними нет.

## Эталон для замера — синтетический

Качество разметки меряем на картах, которые сами и нарисовали: у них известны и сетка, и стены,
и двери, поэтому эталон получается бесплатно. Настоящие карты берём для времени, памяти
и «похоже ли на правду» — глазами.

Ручная разметка одной карты — 20–40 минут скучной работы, а на восьми картах это вечер.
Синтетика даёт те же числа «нашли / ложных» без вечера; на реальных картах цифры всё равно были
бы про одну конкретную карту.

Синтетик три: квадратная сетка 70 px, гексы углом вверх и поворот на 12°. Настоящих карт три,
и их свойства — напечатанная сетка (у двух), её отсутствие (у одной), доски палубы под своим
углом и водяной знак поверх карты. Стен у настоящих карт в эталоне нет: размечать их руками —
тот самый вечер, поэтому «нашли / ложных» считается только по синтетике.

## Сборка и проверка

Программа — Python 3.12; ONNX Runtime и веса приедут вместе с первым рабочим шагом. Язык выбран
по той же причине, что у подготовки: ONNX Runtime здесь родной, а общая библиотека и веса всё
равно едут рядом с программой. Как упакован пакет — открытый вопрос
([../docs/open-questions.md](../docs/open-questions.md)).

```sh
cd annotator
python3 -m unittest discover -s tests -v      # командная строка, без установки
python3 -m vtt_annotator --version            # vtt-annotate 0.1.0
python3 -m pip install '.[check]'             # необязательно: команда и проверка контракта
python3 tests/check_preview.py                # инвариант PREVIEW.md
python3 ../scripts/validate_annotation.py --cases ../contract/cases
```

Коды возврата — из «Интерфейса» выше. Пока разметчика нет, любой режим отвечает 2 и говорит
об этом в stderr: файл не пишется ни при каком исходе.

## Состояние

Разметчика нет: он пишется с нуля, черновик под эксперимент в проект не переносится. Из кода есть
каркас командной строки с тестами, проверка инварианта предварительного файла
(`annotator/tests/check_preview.py`) и его пример в `annotator/examples/`: они держат договор
с клиентом до того, как появится сам разметчик. Фикстуры появятся здесь, в `annotator/fixtures/`,
но только синтетические: репозиторий публичный, а лицензии настоящих карт не проверены, поэтому
в git они не попадают. Настоящие карты остаются у мастера локально, и только на них меряют время,
память и «похоже ли на правду».
