# Стенд разметчика

Инструмент эксперимента, не проект и не поставка: в пакет не едет, настоящие карты в git
не кладутся. Стенд проверяет разметчик на синтетических картах с точным эталоном и на настоящих
картах мастера глазами.

Пока модель разметчика не выбрана, стенд гоняет **прототип поиска сетки**: находит напечатанную
сетку по профилю яркости и собирает `annotation.json` с одной сеткой. Когда появится настоящий
`vtt-annotate`, его можно подставить через `--annotator-cmd`, и стенд начнёт сравнивать результат
с эталоном, не меняя раскладку.

## Быстрый старт

```sh
python3 scripts/experiments/annotator/fixtures.py   # собрать синтетику в cases/
python3 scripts/experiments/annotator/stand.py      # прогнать по кейсам
open scripts/experiments/annotator/results/summary.txt
```

Стены классическим baseline:

```sh
python3 scripts/experiments/annotator/stand.py --detector classical
python3 scripts/experiments/annotator/stand.py --detector classical-no-suppress \
    --out scripts/experiments/annotator/results-nosuppress
```

`classical` гасит линии сетки перед Canny, `classical-no-suppress` — нет: разница в отчёте
и есть цена ложных стен от сетки. Baseline требует `opencv-python-headless` в dev-venv.

Настоящие карты — отдельным прогоном; в git они не попадают:

```sh
python3 scripts/experiments/annotator/stand.py --in 'тестовый материал'
```

Только сетка, без фикстур и отчётов стенда:

```sh
python3 scripts/experiments/annotator/grid.py --in 'тестовый материал'
```

## Что где лежит

| Файл | Что делает |
|---|---|
| `grid.py` | поиск сетки: шаг, сдвиг, толщина, вердикт; уточняет позиции линий по профилю |
| `classical.py` | baseline без модели: Canny + Хаф, склейка коллинеарных обрывков, подавление сетки |
| `synthetic.py` | генератор пар «карта — маска стен» для обучения |
| `train_walls.py` | обучение маленькой U-Net на синтетике и экспорт в ONNX |
| `model.py` | инференс ONNX-модели плитками и превращение маски в стены |
| `fixtures.py` | синтетические карты и `expected.json` по контракту v1 |
| `score.py` | сравнение результата с эталоном: сетка, стены, двери; `--result` и `--expected` |
| `stand.py` | общий прогон: фикстуры или настоящие карты, контракт, overlay, отчёт |
| `cases/` | сгенерированные фикстуры, в git не попадают |
| `results/` | результаты прогона, в git не попадают |

## Результаты на кейс

```
results/square-70/
  original.png          исходная карта
  result.json           annotation.json, собранный стендом
  expected.json         эталон (у синтетики)
  overlay.png           карта с найденной сеткой
  expected-overlay.png  эталонная сетка поверх карты
  compare.png           исходник | результат | эталон
  score.json            расхождения с эталоном
  report.txt            время, память, контракт, итог
```

`summary.txt` в корне результатов — одна строка на кейс.

## Синтетика

Девять кейсов, у каждого точный эталон:

- `rooms-square` — комнаты со стенами, три двери и две области поверх сетки 70 px;
- `rooms-no-grid` — то же без сетки: проверяет, что baseline не путает стены с сеткой;
- `cave` — ломаные стены пещеры и область лавы без сетки;
- `square-70` — обычная квадратная сетка 70 px, должна находиться;
- `square-70-dark` — тёмная сетка: на ней видно, сколько ложных стен даёт сетка без подавления;
- `square-100-faint` — бледная сетка 100 px, проверяет чувствительность;
- `no-grid` — текстура без сетки, ложного срабатывания быть не должно;
- `square-rotated-12` — поворот 12°: прототип его пока не умеет, в `case.json` стоит
  `prototype_supports_grid: false`, и стенд помечает расхождение как ожидаемое;
- `hex-flat` — гексы: прототип их тоже пока не умеет, пометка та же.

Фикстуры детерминированные: тот же код даёт ту же карту. В git они не попадают — это картинки.

## Эксперименты

Первый прогон — классический baseline без модели. Цифры ниже получены на синтетике
(9 кейсов) и настоящих картах; они не «истина про annotator», а планка, которую модель должна
побить.

| Опыт | Что | Результат |
|---|---|---|
| E1 | baseline на комнатах | 2–3 стены из 4, 12–21 ложная; двери 0 из 3, области 0 из 2 |
| E1 | baseline на пещере | 4 стены из 4, 16 ложных: ломаные стены склеиваются лучше прямых |
| E2 | baseline на настоящих картах | 391–1271 отрезок на карту; контракт проходит, но глазами это мусор |
| E3 | тёмная сетка, подавление вкл/выкл | 0 ложных стен против 62 |
| E4 | U-Net на синтетике | комнаты 3/4 стены и **0 ложных**, пещера 4/4 и **2 ложных**; сетка не даёт стен |
| E4 | U-Net на настоящих картах | 327–1387 стен на карту, контракт ok: синтетика не научила её реальным текстурам |

Вывод: морфология находит стены, но не умеет двери и области и тонет в текстуре; линии сетки
в модель попадать не должны. Это подтверждает решение гасить сетку только во входе модели
и показывает, что модель нужна не «вместо всего», а поверх baseline.

U-Net на синтетике убирает главную беду baseline — ложные стены: на комнатах 0 ложных против
21, на пещере 2 против 16. Двери и области она пока не ищет, а на настоящих картах её ещё
предстоит проверить глазами: синтетика не заменяет реальные текстуры.

Два побочных наблюдения, которые важны для annotator:

- на `rooms-square` прототип сетки её не нашёл: сильные стены перебивают профиль яркости.
  Это отдельная задача поиска сетки, а не baseline стен;
- стена, лежащая ровно на линии сетки, при подавлении стирается вместе с ней. В фикстуре такие
  стены сдвинуты с линий; в реальности это риск, и подавление должно обходить уже найденные стены.

## Модель стен

Маленькая U-Net учится на синтетике (`synthetic.py`) одному: где стены. Вход 192×192, выход —
маска; `model.py` режет карту плитками 192 с перекрытием 48, склеивает вероятности и превращает
маску в отрезки тем же `merge_segments`, что и baseline. Сетка гасится во входе модели.

```sh
python3 scripts/experiments/annotator/train_walls.py --count 320 --epochs 10
python3 scripts/experiments/annotator/stand.py --detector model
```

Модель и веса лежат в `models/` и в git не попадают; результат обучения — `annotator_walls.pt`
и `annotator_walls.onnx`. Двери и области модель пока не ищет: это следующий шаг, когда стены
будут достаточны.

## Как подключить настоящий разметчик

```sh
python3 scripts/experiments/annotator/stand.py --annotator-cmd 'vtt-annotate'
```

Стенд зовёт команду как процесс: `vtt-annotate --image <карта> --out <annotation.json>`, читает
stderr и код возврата. Внутренности разметчика он не импортирует — граница проекта остаётся.

## Подготовка карты

`prep` разметчику не нужен как зависимость: он берёт любую RGB-картинку. В продукте клиент
сначала запускает `vtt-prep`, поэтому разметчик получает нормализованную картинку, но стенд
специально работает с исходниками и синтетикой 2048×1536 без обрезки. Если карта уменьшена
подготовкой, шаг сетки в пикселях другой — это видно по `report.txt`, и на эталоне это
не сказывается.

## Ограничения

- прототип ищет только осевую квадратную сетку: поворот и гексы — следующие шаги;
- классический baseline не ищет двери и области: они есть в эталоне, но в результате пусты;
- стены baseline даёт отрезками Хафа, а не аккуратной полилинией: для счёта хватает, для редактора
  пришлось бы склеивать лучше;
- память в отчёте — пик процесса: он растёт от numpy и FFT и к одной карте не относится.
