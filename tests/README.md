# tests — карты для эксперимента

Одна карта — одна папка. Внутри два или три файла:

| Файл | Что это |
|---|---|
| `original.jpg` | карта, как её увидит разметчик: со всей текстурой и напечатанной сеткой |
| `annotation.json` | разметка в формате `vtt.annotation` ([05](../docs/05-map-annotation.md)) |
| `overlay.png` | та же карта с нарисованной разметкой — по ней и смотрят «похоже ли на правду» |

У синтетических карт `annotation.json` — точный эталон: скрипт сам провёл стены и сам записал,
где они. У настоящих карт эталона стен нет: там записано только то, что действительно
**нашли** — сетка. Стен в этих файлах нет намеренно: рисовать их руками «на глазок» значит
получить эталон неизвестного качества, а сравнивать надо с правдой, а не с ещё одной догадкой.

## Синтетические карты

Их рисует `tools/make_synthetic.py`, поэтому попадание по ним считается в цифрах.

| Папка | Что проверяет |
|---|---|
| `01-square-70px` | квадратная сетка 70 px без поворота; комната 10×10 клеток с полями по 70 px, вода и обломки, две двери; напечатанная сетка на карте совпадает с нашей |
| `02-hex-pointy` | гексы углом вверх, R = 40; стены идут по рёбрам гексов, внутри два каменных столба и водоём |
| `03-rotated-12deg` | та же сетка 70 px, повёрнутая на 12°; наклон автоподбор не ищет — проверяем, что мастер может задать его руками |

## Настоящие карты

Дают время, память и «похоже ли на правду» глазами. Ловушки — это их свойства, а не отдельная
группа карт. Шаг, фаза и **само наличие** сетки проверены численно: в профиле яркости чистых
полос искались провалы, и на позициях, кратных шагу, яркость действительно падает — на 11
оттенков у `04-camp-printed-grid` и на 27–29 у `06-wreck-underwater`, а между линиями провала
нет. У `05-ruins-no-grid` такого провала нет ни при шаге 50, ни 25, ни 40: разница ±2 оттенка,
то есть шум. Это заодно эталон для проверки гипотезы сетки ([05](../docs/05-map-annotation.md)
§5.2): две карты должны дать «подтверждено», одна — «не подтверждено».

| Папка | Размер | Шаг сетки | Что проверяет |
|---|---|---|---|
| `04-camp-printed-grid` | 2160×2160 | 72 px, 30×30 клеток | напечатанная сетка есть и совпадает с гипотезой — проверка должна сказать «подтверждено». Лагерь обнесён частоколом: стены есть, но это не комнаты, а забор и камни; есть брод и вода |
| `05-ruins-no-grid` | 1000×700 | 50 px, 20×14 — **выбор мастера** | сетки на карте нет вообще: проверка должна сказать «не подтверждено», а стены всё равно найти. Стены нарисованы от руки, ни под какой модуль не ложатся, вокруг много обломков — идеальная почва для ложных стен |
| `06-wreck-underwater` | 2800×4000 | 100 px, 28×40 | сетка есть, но лежит поверх карты с рваным контуром и тёмным фоном, и провал на ней вдвое глубже, чем у `04`. Доски палубы идут под своим углом — «похоже на сетку, но не она». В правом нижнем углу водяной знак Patreon: живой пример для [Q40](../docs/03-open-questions.md) |

Откуда взялись файлы (исходные имена): `1682260791410.jpg`, `battlemap35.jpg`,
`SOCIAL-GRIDDED-Underwater-Ship-1.jpg`. **Лицензии не подтверждены** — до публикации их надо
проверить: [04](../docs/04-experiment-map-layout.md) §9 требует карты с известной лицензией,
а у водяного знака на `06` отдельный вопрос — его нельзя стирать, если лицензия запрещает
производные.

В `annotation.json` настоящих карт: сетка и `sha256` картинки, `elements` пустой. Единицы
(`unit`, `units_per_cell`) не заполнены: масштаб этих карт неизвестен, а выдуманный масштаб
хуже отсутствующего. `origin` у `04` и `06` — половина шага (36 и 50): `origin` — центр клетки,
а линии идут по границам, поэтому центр садится между напечатанными линиями.

`overlay.png` настоящих карт тяжёлые (5 и 10 МБ): карта текстурная, а PNG хранит её без потерь.
Это производная копия — её можно удалить и перерисовать одной командой, эталон в ней не живёт.

## Цвета на `overlay.png`

| Цвет | Что значит |
|---|---|
| зелёная линия | стена, уверенность ≥ 0.8 |
| жёлтая линия | стена, 0.5 ≤ уверенность < 0.8 — «посмотри сюда» |
| голубая линия | правка руками (`origin: human`) |
| оранжевая линия со штрихами | дверь: штрихи стоят по краям проёма |
| синяя заливка 30% | вода |
| красная заливка 30% | лава |
| серо-коричневая заливка 30% | тяжёлый рельеф: камни, кустарник, обломки |
| тонкая белая линия | наша сетка (поверх напечатанной на карте) |
| красный крестик в кружке | центр клетки (0,0), то есть `origin` сетки |

Стены с уверенностью ниже 0.5 не рисуются вовсе: они попадают в список «возможно, тут
что-то есть», но картинку не засоряют — [05](../docs/05-map-annotation.md), §9.

## Как пересобрать и проверить

```sh
python3 tools/make_synthetic.py              # перерисовать все синтетические карты
python3 tools/make_synthetic.py --only 02    # только одну
python3 tools/render_overlay.py tests/01-square-70px/annotation.json   # только overlay.png
python3 tools/render_overlay.py tests/04-camp-printed-grid/annotation.json  # сетка по настоящей карте
python3 tools/validate_annotation.py tests/  # проверить все annotation.json
python3 tools/validate_annotation.py --self-test
```

Настоящие карты `make_synthetic.py` не трогает: их `overlay.png` перерисовывается только
через `render_overlay.py`.

Нужны Pillow и numpy — это инструменты рабочей машины. На сервер они не едут: серверная
часть на Go, а разметка приходит готовым json и проверяется валидатором.

## Что здесь важно понимать

- **Координаты — пиксели картинки** (D28). Сетка в json — правило стола, а не свойство
  картинки: `origin` — центр клетки (0,0), поворот по часовой стрелке.
- **Линии сетки идут по границам клеток**, а не через `origin`: `origin` — центр клетки,
  поэтому граница — это `origin ± side/2`. Стены стоят по границам, и сетка обязана лечь
  на них, иначе на `overlay.png` видно две сетки со сдвигом в полклетки.
- **Стена — непрерывный участок, а не «одна линия на ребро».** У пещеры (`02`) стена одна
  на всю границу и рвётся только на двери, а два столба — две отдельные замкнутые стены.
  Поэтому «стен 3» — не ошибка; попадание надо мерить по длине, а не по числу элементов
  ([Q39](../docs/03-open-questions.md)).
- **Напечатанная сетка нарисована прямо на карте** — именно её должна находить проверка
  и стирать стирание ([05](../docs/05-map-annotation.md) §5.2). Своя сетка рисуется поверх
  и заметно ярче, поэтому две сетки не путаются.
- **Вода, лава, обломки — не декор.** У области тип из короткого списка, иначе сервер
  не сможет ответить, можно ли туда встать.
- **Точки на карте, которых нет в разметке** (валун в `01`, камень в `02`, обломок в `03`) —
  это не забытые стены, а мусор для проверки: алгоритм не должен принимать их за стены.
